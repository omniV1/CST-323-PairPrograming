# CST-323-PairPrograming

### Team Workflow Rules

- “We will not commit directly to main.”

- “We will work in separate feature branches.”

- “We will avoid editing the same files unless coordinated.”

- “We will commit in small, descriptive steps.”•“We will use pull requests for integration.

- ”These rules are enforceable and graded

### Why These Rules Matter

These rules exist to:

- Prevent merge conflicts

- Preserve a clean commit history•Make integration predictable

### Mirror professional team expectations Ignoring these rules almost always results in:

- Lost work

- Broken builds

- Frustration
